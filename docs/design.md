# モルック得点計算アプリ 設計書

> 出典: Claude Docs「モルック得点計算アプリ 設計書」（2026-10-06）の全文転記。
> 設計を変更するときはこのファイルを更新し、変更理由を `docs/implementation-plan.md` の「判断ログ」に残す。

## 1. 概要

スマホ1台で、モルックの全プレイヤーの得点を1画面で記録・自動計算するWEBアプリを作る。目標点（標準50点）と超過時の戻り点（標準は目標点の半分）は、ゲーム開始前に変更できる。

| 項目 | 内容 |
| --- | --- |
| アプリ名 | もるっくん（2026-10-06 決定）。画面下に「非公式のアプリです」と表示する |
| 利用者 | 試合中の記録係（プレイヤー本人が兼ねることが多い） |
| 利用端末 | スマートフォン縦向きを主対象。タブレット・PCでも崩れないこと |
| 利用場面 | 屋外。片手操作、日差しの下、手袋・濡れた手でも押せる大きさ |
| 公開環境 | Xサーバー＋サブドメイン `https://play-molkky.onga-mirai-tech.com/` |
| 構成方針 | 単一HTMLファイル、素のJavaScript、外部CDNなし。サーバー側処理・DBなし |
| データ保存 | 端末のブラウザ内（localStorage）のみ。個人情報をサーバーに送らない |

ルールの基準は[日本モルック協会「モルックについて」](https://molkky.jp/molkky/)とする。

## 2. ゲームルールと得点計算仕様

1投の得点は必ず0〜12点のどれかになる。1本だけ倒れたらその番号、複数本なら倒れた本数のため、入力は「0〜12の数字を1つ選ぶ」だけで足りる。どのピンが倒れたかは記録しない（2026-10-06 確認）。

| ルール | 標準値 | 設定変更 | アプリの処理 |
| --- | --- | --- | --- |
| 1本倒し | 番号＝得点 | 不可 | 押した数字をそのまま加算 |
| 複数本倒し | 本数＝得点 | 不可 | 押した数字をそのまま加算（記録係が本数を押す） |
| 勝利 | 目標点ちょうど | 目標点を変更可（標準50） | 合計が目標点と一致した時点でそのプレイヤーの勝利 |
| 超過 | 25点に戻る | 戻り点を変更可（標準は目標点の半分） | 合計が目標点を超えたら戻り点に置き換え |
| ミス（0点） | — | 不可 | 連続ミス回数を+1。得点が入れば0に戻す |
| フォルト | 0点・連続ミスに数える | 連続ミスに数えるか選択可 | 0点として記録。「数える」なら連続ミス+1、「数えない」なら連続ミス回数を変えない |
| 連続ミス失格 | 3回 | 回数を変更可・オフ可 | 規定回数に達したら得点0で失格、以後の順番を飛ばす |
| 失格者以外が1人 | — | 不可 | 残った1人を勝者として終了 |

戻り点の決め方は2通りから選べるようにする。

- **目標点の半分（標準）**: 目標点 ÷ 2、端数は切り捨て（例: 目標35 → 戻り17）
- **任意の点数**: 0以上、目標点未満の整数を直接入力（例: 目標50・戻り0の「ゼロ戻し」ルール）

標準設定は「目標50点・超過したら25点（目標点の半分）・連続3回ミスで失格・フォルトは連続ミスに数える」。大会や仲間内のルールに合わせ、すべてゲーム開始前に変更できる（2026-10-06 決定）。詳しいルールは[公式ルールブック](https://molkky.jp/play/official-rule-book/)を参照。

### 1投ごとの判定フロー

0点なら連続ミスを数え、得点が入れば目標点と比べる。勝利以外はすべて次の手番に戻る。

```
入力(points, fault)
 ├─ フォルトかつ「数えない」 ─→ FAULT（0点、misses は変えない）
 ├─ points = 0 ─→ misses+1
 │                 ├─ 失格ONかつ misses ≥ 規定 ─→ 失格(score=0)
 │                 └─ それ以外 ─→ MISS
 └─ points > 0 ─→ misses=0, next = score + points
                   ├─ next = 目標点 ─→ WIN（試合終了）
                   ├─ next > 目標点 ─→ OVER（score = 戻り点）
                   └─ next < 目標点 ─→ ADD
勝利以外 → 次の「失格していない人」へ
```

## 4. 画面設計

画面は「準備」「試合」「結果」の3つ。1つのHTML内で表示を切り替え、ページ遷移はしない。試合画面だけで全員の得点が見え、入力もできる構成にする。

### 4-1. 準備画面

1. ルール設定: 目標点（数値入力）、戻り点（「半分」「任意」の切替＋数値）、連続ミス失格（スイッチ＋回数）、フォルトを連続ミスに数える（スイッチ）。「標準ルールに戻す」ボタンで50／25／3回／数えるに戻す
2. 設定内容の確認文: 「50点ちょうどで勝ち／超えたら25点に戻る／3回連続ミスで失格（フォルトも含む）」のように1行で表示
3. プレイヤー一覧: 名前入力欄、上下移動、削除。「＋追加」「ランダムに並べる」
4. 「ゲーム開始」ボタン（プレイヤー2人未満、戻り点が目標点以上のときは押せない）

前回のプレイヤー名と設定は自動で入った状態で開く。

### 4-2. 試合画面（メイン）

上から順に次の3段で構成する。

- **上段: 手番表示** — 「ラウンド3　次は ○○ さん」、あと何点で勝ちか、連続ミスが規定回数の1つ手前なら「次ミスで失格」の警告
- **中段: スコアボード** — 全員を投擲順に1行ずつ。各行に 名前／現在点（大きく）／あと何点／ミス印（●○○）／直近の1投。手番の行を色と枠で強調、失格者は灰色＋取り消し線。人数が多い場合はこの段だけスクロールし、手番の行が常に見える位置へ自動で寄せる
- **下段: 入力パッド** — 0〜12を4列×4段の大ボタン（1個 最小56px角）。「0（ミス）」「フォルト」は色を変える。下部に「1投戻す」「履歴」「メニュー」。パッドの上に「1本だけ → ピンの番号 ／ 2本以上 → たおれた本数」と押し方を常に表示する（ボタンがピンの形なので、倒れたピンを選ぶ画面と誤解されないように）

入力すると0.5〜1秒、結果を帯で表示する（例: 「+8 → 33点」「超過！ 53 → 25点」「失格」）。勝者が出たら結果画面へ。

### 4-3. 履歴（試合画面から開くパネル）

公式スコアシート風の表。行＝ラウンド、列＝プレイヤーで、各マスに「得点（累計）」を表示。超過・ミス・失格のマスは記号と色で区別する。

### 4-4. 結果画面

- 勝者名を大きく表示
- 全員の最終点・順位（勝者＞残り点の高い順＞失格者）
- 「同じメンバーで再戦」「準備画面に戻る」「直前の1投を取り消す（誤入力時）」

### 4-5. 見た目と言葉の方針

モルックの木のピン（スキットル）をイメージした、オレンジと茶色の明るい配色にする。子どもから高齢の方まで楽しめるよう、言葉はやさしく話しかける口調にする（2026-10-06 決定）。画面の見本は `docs/design-mockup.html`。

## 5. データ設計

保存するのは「設定」「プレイヤー」「投擲の記録（入力した数字の列）」の3つだけにする。現在点・ミス数・手番・勝者は、毎回この記録を先頭から計算し直して求める。こうすると「1投戻す」は記録の末尾を1つ消すだけで済み、計算のずれが起きない。

### 5-1. 保存データ（localStorage）

```javascript
// キー: "molkky-score:v1:game"（進行中の試合）
{
  "version": 1,
  "settings": {
    "target": 50,            // 目標点
    "resetMode": "half",     // "half" | "custom"
    "resetValue": 25,        // resetMode が custom のときだけ使用
    "missLimitEnabled": true,
    "missLimit": 3,
    "faultCountsAsMiss": true // フォルトを連続ミスに数えるか
  },
  "players": [               // 配列の順＝投擲順
    { "id": "p1", "name": "たろう" },
    { "id": "p2", "name": "はなこ" }
  ],
  "throws": [                // 1投ごとに追加
    { "playerId": "p1", "points": 8, "fault": false, "at": "2026-10-06T10:15:00+09:00" }
  ],
  "startedAt": "2026-10-06T10:10:00+09:00"
}
// キー: "molkky-score:v1:lastSetup"（次回の準備画面の初期値: settings と players）
```

読み書きは必ず try/catch で囲み、保存できない環境（プライベートブラウズ等）でも試合自体は続行できるようにする。

### 5-2. 計算ロジック（純粋関数）

```javascript
function resetPoint(s) {
  return s.resetMode === "half" ? Math.floor(s.target / 2) : s.resetValue;
}

function applyThrow(p, t, s) {   // p = あるプレイヤーの状態, t = { points, fault }
  const points = t.fault ? 0 : t.points;
  if (t.fault && !s.faultCountsAsMiss) return "FAULT";
  if (points === 0) {
    p.misses += 1;
    if (s.missLimitEnabled && p.misses >= s.missLimit) {
      p.score = 0; p.out = true; return "OUT";
    }
    return "MISS";
  }
  p.misses = 0;
  const next = p.score + points;
  if (next === s.target) { p.score = next; return "WIN"; }
  if (next > s.target)   { p.score = resetPoint(s); return "OVER"; }
  p.score = next; return "ADD";
}

// computeState(game): players を {score:0, misses:0, out:false} で初期化し、
// throws を先頭から applyThrow。次の手番＝直前の人の次にいる「失格していない人」。
// 先頭に戻ったらラウンド+1。WIN が出た時点、または残りが1人になった時点で終了。
```

画面は computeState の結果だけを見て描画する（状態を画面側で直接書き換えない）。

## 6. 技術構成とデプロイ

本体は `index.html` 1ファイルで完結させる。PHP・データベースは使わない。公開URLは `https://play-molkky.onga-mirai-tech.com/`（サブドメインのルート）。

デプロイは同じXサーバーで運用中の Disaster Chronicle・遠賀町ナビと同じ方式にする。main ブランチへ push すると GitHub Actions がテストを実行し、公開ファイルだけを rsync（SSH）でサーバーへ同期する。

### 6-1. ファイル構成

| ファイル | 役割 | サーバーに置くか |
| --- | --- | --- |
| `index.html` | HTML・CSS・JavaScriptをすべて内包した本体 | 置く |
| `server/.htaccess` | HTTPS・正規ホスト名への転送、セキュリティヘッダー、キャッシュ抑制 | 置く（`dist/.htaccess` として） |
| `icon-180.png` | スマホのホーム画面に追加したときのアイコン | 置く（任意） |
| `scripts/build.sh` | 公開ファイルだけを `dist/` に集める | 置かない |
| `.github/workflows/deploy.yml` | テスト → `dist/` を rsync で同期（失敗時は別環境で再試行） | 置かない |
| `tests/` `docs/` `README.md` `CLAUDE.md` | テスト・設計・手順 | 置かない |

### 6-2. Xサーバーへの配置

1. サーバーパネル → サブドメイン設定で `play-molkky.onga-mirai-tech.com` を追加（2026-10-06 作成済み、DNS反映待ち）。ドキュメントルートは通常 `/home/<サーバーID>/onga-mirai-tech.com/public_html/play-molkky.onga-mirai-tech.com`
2. DNS反映後、SSL設定で `play-molkky.onga-mirai-tech.com` に無料独自SSLを追加する（反映前は失敗するので時間をおいて再試行）
3. GitHub の Environment `production` に接続情報を登録する（SSH鍵・known_hosts・ホスト名は既存サイトのものを流用、`XSERVER_DEPLOY_PATH` だけ手順1のドキュメントルートにする）。`DEPLOY_ENABLED=true` にするまでデプロイは実行されない
4. main に push → Actions のデプロイ完了後、`https://play-molkky.onga-mirai-tech.com/` をスマホで開いて動作を確認する

rsync は `--delete` で同期するため、デプロイ先は必ずこのサイト専用のディレクトリにする。

### 6-3. `server/.htaccess` の方針

- HTTP と、正規ホスト名以外（`onga-mirai-tech.com/play-molkky.onga-mirai-tech.com/` 経由など）からのアクセスを `https://play-molkky.onga-mirai-tech.com/` へ301転送する
- `index.html` は `Cache-Control: no-cache`（更新後に古い版が表示され続けるのを防ぐ）
- セキュリティヘッダー（HSTS・nosniff・X-Frame-Options・Referrer-Policy・Permissions-Policy）を付ける。HSTSは公開直後は1日で運用し、安定を確認してから1年に延ばす
- CSP は `connect-src 'none'` で外部通信を禁止し、「サーバーへ何も送らない」を仕組みで保証する。1ファイル構成のため script/style は `'unsafe-inline'` を許可する（外部読み込みは禁止のまま）

画面消灯防止（Wake Lock）はHTTPSでしか動かないため、SSLは必須とする。

### 6-4. 対応ブラウザ

iPhoneのSafari、AndroidのChrome（いずれも直近2版）を必須、PCのChrome・Edgeは表示確認のみとする。
